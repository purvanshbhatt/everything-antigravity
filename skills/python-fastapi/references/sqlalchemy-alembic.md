# SQLAlchemy 2.0 async and Alembic

## Engine, session factory and dependency

```python
# db/session.py
from collections.abc import AsyncIterator
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

from app.core.config import get_settings

engine = create_async_engine(
    get_settings().database_url,      # e.g. postgresql+asyncpg://user:pass@host/db
    pool_pre_ping=True,
    pool_size=10,
    max_overflow=5,
)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)

async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:
        yield session
```

Dispose of the engine in the app's lifespan shutdown (`await engine.dispose()`).
Size the pool so that `workers x (pool_size + max_overflow)` stays below the
database's connection limit.

## Models (2.0 typed style)

```python
# models/project.py
from datetime import datetime
from sqlalchemy import ForeignKey, String, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship

class Base(DeclarativeBase):
    pass

class Project(Base):
    __tablename__ = "projects"

    id: Mapped[int] = mapped_column(primary_key=True)
    owner_id: Mapped[int] = mapped_column(ForeignKey("users.id"), index=True)
    name: Mapped[str] = mapped_column(String(100))
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())
    tasks: Mapped[list["Task"]] = relationship(back_populates="project", lazy="raise")
```

`lazy="raise"` turns an accidental lazy load into an immediate error instead of
a confusing `MissingGreenlet` later.

## Queries and transactions

```python
# services/projects.py
from sqlalchemy import select
from sqlalchemy.orm import selectinload
from sqlalchemy.ext.asyncio import AsyncSession

async def list_projects(session: AsyncSession, owner_id: int) -> list[Project]:
    stmt = (
        select(Project)
        .where(Project.owner_id == owner_id)
        .options(selectinload(Project.tasks))
        .order_by(Project.created_at.desc())
        .limit(50)
    )
    return list((await session.scalars(stmt)).all())

async def create_project(session: AsyncSession, owner_id: int, data: ProjectCreate) -> Project:
    project = Project(owner_id=owner_id, **data.model_dump())
    session.add(project)
    await session.commit()
    await session.refresh(project)              # load server defaults such as created_at
    return project
```

- Commit once per unit of work. If an exception escapes before the commit, closing the session (the `async with` in `get_session`) rolls the transaction back.
- Use `session.scalars(stmt)` for ORM rows and `session.scalar(stmt)` for a single value.
- Paginate every list endpoint; never return an unbounded `select`.
- For bulk work, use `insert(...).values([...])` or `session.execute(update(...))` rather than loading rows one by one.

## Alembic

```bash
uv run alembic init -t async migrations       # async template
```

In `migrations/env.py`, set `target_metadata = Base.metadata` and read the URL
from settings rather than hard-coding it in `alembic.ini`.

```bash
uv run alembic revision --autogenerate -m "add projects"
uv run alembic upgrade head
uv run alembic downgrade -1
uv run alembic history --verbose
```

Review every autogenerated file:

- Column renames appear as drop plus add, which loses data. Replace them with `op.alter_column(..., new_column_name=...)`.
- Server defaults, check constraints, enum changes and some index changes may be missed or wrong.
- Adding a `NOT NULL` column to a large table needs a default or a backfill step first.
- Data migrations belong in their own revision, written with `op.execute` or a batched script.

Running `upgrade` against a shared, staging or production database needs
explicit user confirmation and a rollback plan. Prefer expand-then-contract
changes (add, backfill, switch reads, then drop) for zero-downtime deploys.

## Tests against a real database

Use a disposable Postgres (Docker or testcontainers), run
`alembic upgrade head` once per session, and wrap each test in a transaction
that is rolled back:

```python
# tests/conftest.py (excerpt)
import pytest
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine

@pytest.fixture
async def db_session(database_url: str):
    engine = create_async_engine(database_url)
    async with engine.connect() as conn:
        trans = await conn.begin()
        session = AsyncSession(bind=conn, join_transaction_mode="create_savepoint", expire_on_commit=False)
        try:
            yield session
        finally:
            await session.close()
            await trans.rollback()
    await engine.dispose()
```

`join_transaction_mode="create_savepoint"` lets code under test call
`commit()` while the outer transaction still rolls everything back. Override
`get_session` with this fixture through `app.dependency_overrides`.
